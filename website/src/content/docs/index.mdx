## How it works

<div class="kp-section-lead">
Three things separate Keyper from a hosted password manager.
</div>

<div class="kp-points">
<div class="kp-point">
<h3>Encrypted before it leaves the browser</h3>

Secret values are encrypted with AES-GCM on your device. Your master passphrase
unwraps the key that decrypts them, and it never travels to the database.
Titles, usernames, URLs, notes, and tags are stored as regular text so that
search and sorting work.
</div>

<div class="kp-point">
<h3>Your database, not mine</h3>

Point Keyper at your own Supabase project, a Neon Postgres database, or a local
SQLite file. You pick which one in the app's settings. There is no Keyper server
in the middle holding your rows.
</div>

<div class="kp-point">
<h3>Two locks, not one</h3>

Signing in decides whether the database returns your rows at all. Unlocking the
vault decides whether you can read them. On Supabase those are separate
accounts, with the separation enforced by the database.
</div>
</div>

</div>

## Run it where you want

<div class="kp-section-lead">
The same app ships four ways. All of them talk to the database you configured.
</div>

<ul class="kp-runtimes">
<li><strong>Hosted web app</strong><span>Use app.keyper.icu and point it at your own database.</span></li>
<li><strong>Installable PWA</strong><span>Install from the browser for an app window and an icon.</span></li>
<li><strong>Docker</strong><span>An nginx image you can run on your own hardware or NAS.</span></li>
<li><strong>Desktop</strong><span>Windows installer, Linux AppImage, and .deb packages.</span></li>
</ul>
